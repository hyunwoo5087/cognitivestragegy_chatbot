# 메타인지·AI활용 성찰 지원 시스템 (CognitiveStrategy Chatbot)

본 프로젝트는 **초중등 학습자의 메타인지 능력 신장**과 **인간-AI 간 협력적 성찰 역량 함양**을 목표로 도출된 **13대 교육공학적 설계원리**를 구현한 프로토타입입니다.

핵심 원칙: **“어디서 설정하고, 어디서 대화하고, 어디서 되짚는가”는 서로 다른 화면이어야 한다.** 다만 세션의 준비(사전지식 활성화·메타인지 점검)는 검사지 같은 폼이 아니라 **튜터와의 대화 안에서 자연스럽게** 이루어지며, 되짚기·잔여물 확인만 별도의 비대화 화면으로 분리됩니다.

Upstage **Solar Pro** 기반. 계정별로 세션이 **서버(Google Sheets)에 누적 저장**되어, 다른 기기·브라우저에서 다시 로그인해도 지난 대화·자주 쓴 인지전략·메타인지 응답 이력이 그대로 이어집니다. (localStorage 미사용)

### 화면 흐름

| 화면 | 성격 | 하는 일 |
| :--- | :--- | :--- |
| **로그인 / 회원가입** | 비대화 | 닉네임 + **그림 4개 잠금**(슬롯 돌리기·정지 또는 직접 선택). 저연령 진입장벽 완화. 계정은 **Google Sheets**에 저장(그림비번은 pbkdf2 해시), 세션은 **HttpOnly 쿠키** |
| **내 학습터 (누적)** | 비대화 대시보드 | 지난 세션 목록 · **내가 자주 고른 인지전략**(막대) · 주도/위임 누적 비율(도넛) · 세션별 지원강도 추이 · **메타인지 점검 응답 모음** |
| **세션 시작** | 슬림 폼 | 학년만 고르고, **오늘 공부하고 싶은 것을 자유 서술**로 적으면 낱말·교육과정 해설 기준으로 **성취기준을 자동 매칭**(+선택적 목표 1줄). 원치 않으면 접이식 “직접 과목·단원 고르기”로 기존 방식도 그대로 쓸 수 있음 |
| **대화** | 채팅 | 준비 대화(인사→목표→사전지식→이해도 1~5 인라인→메타인지 3문항)→탐구 대화. **전략 선택 칩**, 모든 AI 응답에 **수용/보류/코멘트**, 지원강도 배지(수용 누적 시 자동 옅어짐), **“나 지금 막혔어”**, 인라인 역할 조정, 자유 입력 상시 |
| **되짚기** | 비대화 대시보드 | 턴별 **내 주도/AI 위임** 태깅 타임라인 · 질문유형 도넛 · 수용 분포 · 되짚기 서술 |
| **잔여물 확인** | 비대화·AI 배제 | 지연 후 별도 세션. 근접·원거리 전이 2문항(시험지형) · 자기설명 필수 · 확신도 슬라이더 · **4축 근거**(절차적 정확도만 규칙기반, 나머지는 근거만·판정 안 함) · 전후 비교 · 델타는 학습자가 수용/보류/코멘트 · 다음 세션 시작 지원강도를 학습자가 선택 |

### 성취기준 데이터 (초3 ~ 고1)

`curriculum_standards.js` 는 **2022 개정 교육과정 성취기준 1,491건**을 담고 있으며,
[greatsong/k-curriculum-2022](https://github.com/greatsong/k-curriculum-2022) 데이터셋(교육부 고시 별책 원문, **CC BY 4.0**)에서 초3~고1 범위를 추출·정리한 것입니다. 각 항목은 `code`·`area`·`name` 외에 **(v11)** 원본 데이터셋의 `explanation`(공식 해설, 260자로 요약)을 `concept`으로, `keywords`를 `kw`로 함께 담고 있어 성취기준 자동 매칭과 AI 응답 그라운딩에 쓰입니다. 재생성은 `gen_curriculum.mjs`(원본 `standards.json` 필요) 참고.

> **학년 선택 vs 성취기준 단위**: 세션 시작 화면의 학년 드롭다운은 **초3·초4·초5·초6·중1·중2·중3·고1을 개별 선택**합니다. 다만 2022 개정 교육과정은 성취기준을 **학년군**(3~4학년군 / 5~6학년군 / 중1~3학년군 / 고1 공통)으로 고시하므로, 같은 학년군에 속한 학년(예: 초5·초6)은 동일한 성취기준 목록을 공유합니다. 개별 학년별로 분리된 공식 성취기준은 존재하지 않습니다. `index.html` 의 `bandOf(grade)` 가 선택 학년을 해당 학년군 데이터로 매핑하며, 선택한 개별 학년은 세션(`ctx.grade`)과 AI 프롬프트(`[학습자 학년]`)에 별도로 전달되어 어투·난이도 조절에 쓰입니다.
>
> 학년군별 규모: 3~4군 9과목 231건 · 5~6군 10과목 280건 · 중1~3군 14과목 714건 · 고1 9과목 266건.

## 🗄️ 백엔드 / 데이터 저장 (v12: Redis → Google Sheets)

계정·학습 데이터 저장소를 Vercel Marketplace Redis에서 **Google Sheets**로 옮겼습니다(사용자 요청). `api/_store.js`가 `kvGet`/`kvSet`/`kvSetNX`/`kvDel`이라는 동일한 key-value 인터페이스를 유지한 채 내부 구현만 Sheets REST API 호출로 바꿨기 때문에, `api/auth.js`·`api/data.js`는 전혀 손대지 않았습니다.

| 데이터 | 위치 |
| :--- | :--- |
| 계정(닉네임 → `{pbkdf2 해시, salt, 생성일}`) | 스프레드시트 **Users** 탭 (nickname · pin_hash · pin_salt · created_at) |
| 학습 데이터(세션 전체) | 스프레드시트 **Sessions** 탭, **세션 1개 = 행 1개** (nickname · session_id · started_at · session_json · updated_at) |
| 세션 인증 | `sess` **HttpOnly·Secure·SameSite=Lax 쿠키** (HMAC 서명 토큰, 90일) |
| Upstage API 키 | Vercel 환경변수 `UPSTAGE_API_KEY` (브라우저 미노출) |

두 탭과 헤더 행은 **앱이 처음 호출될 때 자동으로 만듭니다**(탭이 없으면 만들고, 헤더가 비어 있으면 채웁니다) — 시트를 미리 손으로 세팅할 필요가 없습니다. 성취기준(`curriculum_standards.js`, 1,491건)은 정적 참고자료라 그대로 앱에 내장했습니다(매번 시트에서 불러오면 느려지고 API 한도에도 민감해져서, 계정·학습기록처럼 자주 바뀌는 데이터만 시트로 옮기는 게 낫다고 판단했습니다).

**API 엔드포인트**
- `POST /api/auth` — `{mode:'signup'|'login'|'logout', nickname, pin}` → `sess` 쿠키 발급/삭제
- `GET /api/data` — 쿠키 인증 후 내 학습 데이터 반환
- `PUT /api/data` (또는 `POST`, `navigator.sendBeacon`용) — 내 학습 데이터 통째로 저장(세션마다 내용이 바뀐 행만 다시 씀)
- `POST /api/chat` — Upstage Solar Pro 프록시(키는 서버에만)
- `POST /api/ocr` — 손글씨(수학) 이미지를 Google Cloud Vision으로 텍스트 변환하는 프록시 **(v12)**

**환경변수 (Vercel 프로젝트 `repo`)**
- `GOOGLE_CLIENT_EMAIL` — Google 서비스 계정 이메일
- `GOOGLE_PRIVATE_KEY` — 그 서비스 계정 JSON 키의 `private_key` 값
- `GOOGLE_SHEET_ID` — 스프레드시트 URL의 `/d/` 뒤 긴 문자열
- `AUTH_SECRET` — 세션 토큰 HMAC 서명 키 (48바이트 랜덤)
- `UPSTAGE_API_KEY` — Upstage 콘솔 발급 키

로컬 개발: `vercel env pull .env` 후 `vercel dev`.

### Google Sheets 백엔드 + 손글씨 인식(Cloud Vision) 설정 — 처음 1회

Sheets 저장과 수학 손글씨 인식은 **같은 Google 서비스 계정 자격증명**을 함께 씁니다(스코프만 둘 다 요청). 아래 순서대로 한 번만 설정하면 됩니다.

1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트를 새로 만들거나 기존 프로젝트를 고릅니다.
2. **API 및 서비스 → 라이브러리**에서 **Google Sheets API**와 **Cloud Vision API**를 각각 검색해 **사용 설정**합니다.
3. **IAM 및 관리자 → 서비스 계정 → 서비스 계정 만들기**로 새 서비스 계정을 만듭니다(프로젝트 수준 역할은 부여하지 않아도 됩니다 — 시트 접근 권한은 4번에서 시트 자체를 공유해서 줍니다).
4. 만든 서비스 계정의 **키 탭 → 키 추가 → 새 키 만들기 → JSON**을 눌러 JSON 키 파일을 내려받습니다. 그 안의 `client_email`과 `private_key` 값을 기억해 둡니다.
5. 대상 스프레드시트([시트 링크](https://docs.google.com/spreadsheets/d/1Wvgf_ni2RcaC55VNA1aZgm0B-6XuZMemBe_YrJ8kUcs/edit))를 열고 **공유** 버튼을 눌러, 4번의 `client_email` 주소를 **편집자**로 추가합니다(알림 보내기는 꺼도 됩니다).
6. Vercel 프로젝트에 환경변수 3개를 등록합니다:
   ```bash
   vercel env add GOOGLE_CLIENT_EMAIL production   # 4번의 client_email
   vercel env add GOOGLE_PRIVATE_KEY production     # 4번의 private_key (그대로 붙여넣기, -----BEGIN PRIVATE KEY----- 포함)
   vercel env add GOOGLE_SHEET_ID production         # 1Wvgf_ni2RcaC55VNA1aZgm0B-6XuZMemBe_YrJ8kUcs
   ```
7. `vercel --prod` 로 재배포하면 첫 요청 때 **Users**·**Sessions** 탭과 헤더 행이 자동으로 만들어집니다.
8. (정리) 더는 안 쓰는 Vercel Marketplace Redis 통합(`redis-red-magnet`)은 Vercel 프로젝트 설정의 **Integrations**에서 해제하고, `REDIS_URL` 환경변수도 지우면 됩니다.
9. **손글씨 인식(Cloud Vision)을 쓰려면 결제(Billing)를 반드시 연결해야 합니다** — Sheets API는 결제 없이도 되지만, Cloud Vision API는 무료 사용량이 있어도 프로젝트에 결제 수단이 걸려 있어야 호출 자체가 열립니다. [Google Cloud Console](https://console.cloud.google.com/) → 좌측 메뉴 **결제(Billing)** → 이 프로젝트에 결제 계정을 연결(또는 새로 만들기)하세요. 안 해두면 `/api/ocr` 호출 시 `This API method requires billing to be enabled` 오류가 그대로 뜹니다(코드로 우회할 수 없는, Google 쪽 제약입니다).

> [!NOTE]
> 시트 한 칸(cell)은 최대 약 5만 자까지 담을 수 있어요. 한 세션의 대화가 아주 길고 구조화 자료(마인드맵 등)가 많이 쌓이면 이 한도에 닿을 수 있습니다(드문 경우로 예상). 이번 버전엔 별도 경고 없이 저장 실패로만 나타나니, 실사용 중 자주 발생하면 세션을 여러 행으로 나누는 방식으로 개선이 필요합니다.
> `kvSetNX`(닉네임 중복 가입 방지)는 Sheets에 진짜 원자적 연산이 없어 "읽고-없으면 추가"로 흉내만 냅니다 — 같은 닉네임으로 동시에 가입 요청이 오는 극히 드문 경우엔 경합이 있을 수 있습니다.

## 🔑 Upstage API 키 설정 — 세 가지 중 하나

`index.html` 상단 `callLLM()` 은 아래 우선순위로 키를 찾습니다.

1. **코드에 직접 고정** — `index.html` 스크립트 최상단의 `const FIXED_API_KEY = "";` 에 키를 넣으면 프록시 없이 브라우저에서 바로 호출합니다. (공개 저장소에 올리면 노출되니, 사설/사내 배포에서만 사용하세요.)
2. **서버 환경변수 (권장, 현재 Vercel 배포 방식)** — `FIXED_API_KEY` 를 비워 두면 프론트엔드는 `/api/chat` 프록시만 부르고, 실제 키는 Vercel 프로젝트의 환경변수 `UPSTAGE_API_KEY` 에만 있습니다.
3. **브라우저 localStorage** — 정적 호스팅에서 개발자 콘솔로 `localStorage.setItem('UPSTAGE_API_KEY','up_...')` 하면 그 브라우저에서만 직접 호출합니다.

> [!WARNING]
> 과거 커밋에 테스트 키가 하드코딩되어 공개된 적이 있습니다. 그 키는 Upstage 콘솔에서 폐기·재발급하세요. 새 키를 방법 1로 넣을 경우 저장소가 공개면 노출됩니다.

### Python(Streamlit) 로컬 실행용 `.env` 설정

```env
# Upstage 개발자 콘솔 (https://console.upstage.ai/)에서 발급받은 API 키
UPSTAGE_API_KEY=여기에_발급받으신_키를_붙여넣으세요

# 모델 설정 (기본: solar-pro)
UPSTAGE_MODEL=solar-pro
UPSTAGE_BASE_URL=https://api.upstage.ai/v1
UPSTAGE_REASONING_EFFORT=medium
```
> [!IMPORTANT]
> `.env` 파일은 `.gitignore`에 등록되어 있어 git에 커밋되지 않습니다. 소스 코드를 수정할 필요 없이 `.env` 값만 입력/변경하면 됩니다.

## ▲ Vercel 배포 (API 키 안전하게 보관하기, 권장)

`index.html` + `api/chat.js`(서버리스 프록시)를 함께 배포하면, 학습자는 아무 설정 없이 바로 사용할 수 있고 API 키는 서버에만 존재합니다.

```bash
# 1. Vercel 로그인 (최초 1회, 브라우저 인증)
vercel login

# 2. 프로젝트 루트에서 배포
vercel --prod

# 3. API 키를 Vercel 환경변수로 등록 (배포와 별개로 1회 설정)
vercel env add UPSTAGE_API_KEY production
# -> 프롬프트가 뜨면 Upstage 콘솔에서 발급받은 키 값을 입력

# 4. 환경변수 반영을 위해 재배포
vercel --prod
```

배포가 끝나면 `https://<프로젝트명>.vercel.app` 형태의 URL이 발급됩니다. 이 URL이 API 키가 노출되지 않는 **정식 서비스 주소**입니다.

| | **7. 메타인지적 지식 점검(나 단계)** | 가 단계 다음, 먼저 **"평소 이 내용은 보통 어떻게 공부해?"** 한 줄을 받아 학습 습관을 남긴다. 그다음 **이해 스캐폴딩**(확신이 안 서는 부분+이유, 직전의 자신감 점수와 겹치지 않도록 숫자 재질문 금지) → **전략 스캐폴딩**(접근 순서+이유) → **연결 스캐폴딩**(이전 개념·실생활 연결)을 한 턴에 하나씩, 서로 다른 발문으로 명확히 구별해서 순서대로 물음(Kramarski & Mevarech, 2003). 답변은 AI가 이해/전략/연결 3축으로 각각 루브릭 채점해 카드로 보여주고(평소 공부법 한 줄도 함께), 계정에 누적되어 **내 학습터**에 쌓임. **(v16)** 세 스캐폴딩에 다 답해도 "다. 방법 정하기"로 못 넘어간다는 버그 신고 — `session.meta.step`이 문턱(3)에 닿는 시점과 `[다음으로]` 버튼의 표시 여부를 계산하는 `paintPhase()` 호출 시점이 어긋나 있었다(값은 바뀌지만 화면이 안 바뀜). 세 번째 스캐폴딩 답을 처리한 직후 `paintPhase()`를 호출하도록 수정 |
| **대화 (인지전략 조절, 나선형 순환)** | **8. 인지 전략 계획 수립(다 단계)** | Weinstein & Mayer(1983)·Pintrich et al.(1993)의 5대 유형(시연·정교화·조직화·비판적 사고·이해 점검)을 카드로 제시, **1개 이상 복수 선택** 가능. **(v13)** "인지전략 선택이 학습자의 메타인지·교과지식과 맞아야 하지 않냐"는 지적을 반영해, 카드를 보여주기 전에 **가·나 단계에서 나온 내 정보**(아는 것 확인 점수·자신감·이해/전략/연결 점수)를 요약 패널로 먼저 보여준다(참고용, 방법을 대신 정해주지 않음). 카드에서 영문 이론명(Rehearsal 등)은 빼고 쉬운 설명만 남겨 더 친숙하게 다듬음. 고른 직후 “그 방법을(들을) 고른 이유가 뭐야?”를 반드시 묻고 답을 받아(`strategyReason`) 이후 모든 대화의 시스템 프롬프트에 근거로 실음(방법 고르기와 이유 말하기는 진행 단계 표시상 하나의 단계로 묶임). 여러 방법을 골랐으면 “방법대로 해보기” 턴마다 방법을 돌아가며 적용. **(v10)** 전략 자체(반복 연습·예시 연결 등)는 과목 공통이지만 “무엇을” 반복·예시로 들지는 과목마다 달라야 한다는 지적을 반영해, “방법대로 해보기” 지시에 지금 과목(국어/영어/수학/사회/과학)에 맞는 소재로 구체화하라는 명시적 지침을 추가(영어=철자·문장, 수학=풀이 순서·검산 등). **(v12)** 소재 구체화를 넘어 **입력 방식 자체**도 과목마다 다르면 좋겠다는 지적을 반영 — 국어·사회·과학은 대화(주지주의적 어포던스)로 충분하다고 보고 그대로 두되, 영어는 대화창에 **🎤 말해서 입력하기**(브라우저 내장 음성인식, `en-US`)와 AI 말풍선 **🔊 영어 발음으로 들어보기**(브라우저 내장 TTS)를 추가했고, 수학은 **✍️ 손글씨로 풀기**(캔버스에 쓰면 Google Cloud Vision OCR이 텍스트로 바꿔주고, 학습자가 고친 뒤 입력창에 넣음)를 추가함. 셋 다 과목이 그 값일 때만 나타남 |
| | **9. 학습 과정 모니터링 기반 조정** | 탐구 대화는 화면 상단 **나선형 순환 절차 바**를 따라간다: **①질문 받기 → ②방법대로 해보기(시행) → ③점검하고 판단하기(평가) → ④계속할지 바꿀지 정하기(조정) → (다시 ①로 반복)**. ④에서 매 바퀴마다 지금 방법이 맞는지 스스로 되묻고, 바꾸고 싶으면 헤더의 **“🔄 방법 바꾸기”**로 직접 실행(바꾼 직후 “왜 바꿨어?”를 물어 이유를 기록). 입력창 옆 **“막혔어요”** 버튼은 안 고른 다른 방법을 구체적으로 이름 붙여 제안. “잘 모르겠어요” 판단이 2번 쌓이면 학습자가 누르지 않아도 **시스템이 먼저** 점검·조정을 제안. **(v8)** 이해 전략(이해 점검) 선택 여부와 무관하게, **이해도 체크포인트**가 대화 중 자동으로 뜨고, 1~5점 확신도와 **그 이유를 반드시 함께** 입력해야 다음 대화로 넘어갈 수 있음(점수만 내고 넘어가는 UX 지양). **(v9)** 간격을 선생님이 미리 숫자로 정하던 방식을 없애고, AI가 대화 신호를 보고 그때그때 적응적으로 판별하도록 바꿈 — 지원강도에 연동한 기본 주기(서툴수록 자주) 위에, “잘 모르겠어요” 판단·“막혔어요”·공부 방법 변경처럼 이해가 흔들렸다는 신호가 잡히면 그 즉시 앞당겨서 체크포인트를 띄움. **(v11)** 체크포인트 점수(1~5)가 기록만 되고 실제로 아무 데도 안 쓰인다는 지적을 반영 — 낮게(1~2점) 표시하면 **다음 AI 응답이 실제로 더 쉬운 말·예시로 다시 설명**하도록 한 번 반영되고(적응 루프를 닫음), 되짚기 화면에 체크포인트 추이 **꺾은선 그래프**가 새로 생김. 카드에 “이 점수가 무엇에 쓰이는지” 설명 문구를 추가. **(v13, 원리9 라 단계)** 점검(check) 질문이 "왜 그렇게 생각했어?"에 그치지 않고, ①아직 헷갈리는 부분이 있는지 ②방금 쓴 방법이 실제로 도움이 됐는지 ③안 맞았다면 어디서 어떻게 걸렸는지(순서를 헷갈림·뜻을 착각함 등, 오류 유형)를 학습자 스스로 짚어보게 묻도록 지시를 구체화. 조정(adjust) 단계에서도 안 맞았다는 신호가 보였으면 방법을 바꿀 기회라는 것을 짧게 짚어주도록 함(최종 판단은 여전히 학습자) |
| | **10. AI 기반 응답 검증 및 수용 여부 판단** | 모든 AI 응답(표·마인드맵·드릴·체크리스트 같은 산출물 포함) 아래 **판단하기** 단일 버튼 → 누르면 팝업에서 좋아요/잘 모르겠어요/다른 생각 중 하나를 고르고, 다른 생각이면 코멘트 입력. 버튼 자체가 지금 판단 상태를 표시. 수용 이력이 원리 1 자동 페이딩·원리9 모니터링의 근거. **(v10)** 학습자가 마인드맵·드릴·체크리스트처럼 직접 수행하는 산출물에는 “🔍 다 했어요 — AI한테 보여주기” 버튼을 추가 — 누르면 AI가 그 결과(마인드맵 낱말·연결, 외운 항목, 아는/헷갈리는 항목)를 보고 잘한 점 1가지와 다시 생각해볼 점 1가지를 피드백함(맞다/틀리다를 AI가 단정하지 않고 되짚어 묻는 방식) |

| **직후 성찰 (대화 이후, Step-by-Step)** | **11. 학습자-AI 간 역할 및 위임 성찰(가)** | 되짚기 1단계: 전체 대화를 펼쳐 놓고, 내가 한 말 중 **“내가 생각”·“AI에게 맡김”을 직접 골라** 다음으로 진행. 왜 그렇게 나눴는지 서술하는 칸도 별도로 있음. **(v11)** 서술이 막막할 때만 쓰는 **“질문 하나 받기”** 버튼 추가 — AI가 성찰문을 대신 써주지 않고, 이번 대화의 실제 한 장면을 짚어 “왜 그랬는지” 묻는 질문 1개만 만들어 준다(원리2: 쓰는 것은 끝까지 학습자 몫). 체크포인트 추이·방법을 바꾼 기록·이번에 만든 산출물·과업 분담 요약도 이 화면에 함께 모아 보여줌. **(v13)** 대화내역을 가로 스크롤 카드열 대신 **세로 목록(좌측 칸)**으로 바꿔 한 번에 하나씩 읽으며 표시하기 쉽게 함. ### v5에서 바뀐 점
- **AI 응답 판단을 버튼 3개 → 1개로** — 말풍선마다 다닥다닥 붙어있던 “좋아요/잘 모르겠어요/다른 생각”을 **판단하기** 단일 버튼으로 통합. 누르면 팝업에서 판단(+다른 생각이면 코멘트)을 남기고, 버튼 자체가 현재 판단 상태를 표시
- **AI 도움 정도는 대화 시작 전에만 설정** — 세션 시작 화면에서 처음 지원강도(많이/보통/조금)와 역할분담(힌트~첨삭)을 한 번 정하면, 대화 중에는 더 이상 손으로 바꿀 수 없고 **“좋아요” 판단이 2번 쌓일 때만 자동으로 한 단계씩 소거**됨(원리1 순수 적응형 페이딩)
- **마크다운 금지** — 시스템 프롬프트에 서식 규칙을 명시하고, 혹시 새어 나온 `**굵게**`나 `#제목`, 목록 기호 등은 `stripMarkdown()`이 방어적으로 한 번 더 제거
- **상단 진행 단계 바** — 화면 최상단에 `① 대화 시작 전 → ② 대화 중 → ③ 대화 이후` 3단계 진행 상황을 항상 표시
- **탐구 대화의 순환 절차를 시각화 + 실제로 구현** — 대화 중에는 진행 단계 바 아래에 `① AI가 발문 → ② 방법대로 해봐요 → ③ 점검 질문 받아요 → ④ 내가 판단해요 → (반복)` 루프를 보여주고, 실제 시스템 프롬프트도 이 3단계(발문/전략적용/점검)를 순서대로 돌며 생성함 — 예전처럼 전략과 무관하게 매번 같은 톤의 발문만 반복하지 않음
- **인지 전략 선택을 더 구체적으로** — 방법을 고른 직후 “왜 그 방법을 골랐어?”를 반드시 물어 그 이유(`strategyReason`)를 받고, 이후 모든 대화의 시스템 프롬프트에 함께 실어 방법이 실제로 그 이유에 맞게 적용되도록 함
- **공부 방법별 구조화 산출물** — 줄글로 표현하기 어려운 결과를 실제 어포던스로 산출: 정리하기→**표/마인드맵**, 따져보기→**비교(내 생각 vs 반박)**, 이유 찾기→**원인→결과 사슬**, 예시로 알기→**예시 표**. 대화창의 “빠른 버튼”을 누르면 AI가 순수 JSON으로만 응답하고 프론트가 실제 HTML 표·마인드맵·비교표·사슬 다이어그램으로 렌더링(마크다운 문법을 전혀 쓰지 않음)

### v6에서 바뀐 점
- **인지 전략을 이론에 맞게 재정렬 + 복수 선택** — 라벨을 Weinstein & Mayer(1983)·Pintrich et al.(1993)의 5대 유형(시연·정교화·조직화·비판적 사고·이해 점검)에 정확히 대응시키고(`theory` 필드로 명시), 1개만 고르던 것을 **1개 이상 복수 선택**으로 변경. 방법마다 서로 다른 산출물(드릴·표·마인드맵·비교·체크리스트)을 매칭해 더 구체적으로 특화
- **과업 분담을 블록으로(원리5)** — 세션 시작 화면에 “개념 설명·예시 들기·답 확인·요약”을 AI/학습자 블록으로 클릭해 옮기는 UI 추가. 공부 방법 정하기·AI 말 수용 판단·성찰 쓰기는 항상 학습자 몫으로 **잠가서 AI로 옮길 수 없게** 함. 이 분담은 매 턴 시스템 프롬프트에 실려 AI가 실제로 지킴(장식이 아님)
- **학습목표 명확화 게이트(원리4)** — 목표 답변이 너무 짧거나 “몰라요” 같은 무의미한 대답이면 다음 단계(사전지식 활성화)로 못 넘어가고 AI가 구체적으로 다시 물음
- **이해·전략·연결 스캐폴딩 명확히 구별(원리7)** — 세 질문을 서로 다른 발문 템플릿(확신 점수+이유 / 접근 순서+이유 / 이전 개념·실생활 연결)으로 한 턴에 하나씩 순서대로 물어, 뭉뚱그려 묻던 것을 확실히 구별
- **모니터링 기반 조정이 실제로 작동(원리9)** — 이전에는 학습자가 “막혔어요”를 누르지 않으면 방법 조정이 전혀 일어나지 않았음. 이제 ①“잘 모르겠어요”가 2번 쌓이면 시스템이 먼저 점검·방법 조정을 제안(`suggestStrategyCheck`), ②헤더의 “🔄 방법 바꾸기”로 대화 중 언제든 방법을 더하거나 빼고, 바꾼 이유를 곧바로 물어 기록(`strategyChangeLog`), ③“막혔어요”가 지금 안 고른 방법의 이름을 구체적으로 제안
- **성찰을 Step-by-Step 가·나·다·라로 분리(원리11·12·13)** — 되짚기 화면을 “가: 역할·위임 성찰(전체 대화에서 내가 생각한 것 3개·AI에게 맡긴 것 3개를 직접 골라야 다음으로 감) → 나: 프롬프트 성찰(내가 쓴 질문만 다시 나열해 보여줌)”로 분리하고, 잔여물 확인 앞에 “다: 이번엔 어떤 인지 전략으로 답할지 스스로 고르기”를 추가(라: 전후 비교는 기존 유지)
- **AI 산출물 판단이 표·마인드맵에도** — 구조화 산출물(표/마인드맵/비교/드릴/체크리스트) 말풍선에도 판단하기 버튼이 동일하게 붙어, 산출물 자체의 수용 여부를 중간중간 표기할 수 있음(기존에 이미 구현되어 있었음을 재확인)

### v7에서 바뀐 점 (v6 실사용 중 발견한 3가지 어색함 수정)
- **“아는 것 나누기”와 “사전 진단” 중복 제거(원리6)** — v6까지는 자유 대화로 아는 것을 나눈 직후, 같은 내용을 다시 묻는 4문항 퀴즈를 별도로 봤음(활성화와 점검이 겉보기에 똑같아 보임). 이제 그 퀴즈를 없애고, **방금 나눈 대화 내용을 AI가 그대로 채점**해 사전 진단 점수를 만듦. 진행 단계도 6단계→5단계로 줄어듦
- **“스스로 점검”의 이해 스캐폴딩이 자신감 점수와 겹치던 문제 수정(원리7)** — 이해 스캐폴딩이 “1~5점으로 다시 말해줄래?”를 예시로 갖고 있어서 직전 자신감 점수 단계와 사실상 같은 걸 두 번 묻고, AI도 헷갈려 함(실사용 캡처로 확인). 이제 숫자 재질문을 명시적으로 금지하고 “확신이 안 서는 부분이 어디인지”만 묻도록 고정
- **“방법 고르기”와 “이유 말하기”를 한 단계로 통합** — 두 개의 어색한 별도 단계처럼 보이던 것을, 진행 표시상 “방법 고르고 이유 말하기” 하나로 합침(내부 로직은 그대로, 표시만 수정)
- **나선형 순환 구조 명시(원리8·9)** — 기존 “발문→시행→점검→(판단)” 3단계 반복에 **“조정”을 4번째 실제 생성 단계로 추가**해 시행→평가→조정→시행→평가→조정… 나선이 순환 절차 바에 그대로 보이게 함. “조정” 턴마다 AI가 “계속 쓸까, 바꿔볼까”를 스스로 묻고, 실제 변경은 학습자가 [🔄 방법 바꾸기]에서 실행
- **마크다운 구분선(“---”) 방어 처리** — AI 응답이 번호 목록과 함께 “---” 같은 구분선만 앞에 남기고 잘려 “---. 너는 어떻게 생각해?” 식으로 깨지던 버그 수정(`stripTaskDump`가 구분선·문장부호만 남은 경우도 안전 문구로 대체)

### v8에서 바뀐 점 (인지전략별 어포던스 차별화 — 5개 중 2개 프로토타입)
전략을 “카드 고르고 나서는 결국 다 똑같은 채팅”이 되지 않도록, 이해 점검과 조직화(마인드맵) 두 전략에 각 전략에 고유한 인터랙션을 붙였다. 공통 원칙은 (1) 구조·관계·최종 판단은 항상 학습자 몫, AI는 후보만 제시 (2) 지원강도에 연동한 적응적 페이딩 (3) 위젯 산출물은 세션에 그대로 저장되어 되짚기/잔여물 확인에서 재사용 가능하다는 것.
- **이해 전략 — 이해도 체크포인트(원리9)** — 대화 중간에 자동으로 카드가 뜬다(간격 설정은 v9에서 완전 자동으로 바뀜, 아래 참고). 1~5점 확신도 칩과 **그 이유를 적는 칸이 한 세트**이고, 점수만 고르고 이유를 비워두면 “확인하고 계속하기” 버튼이 비활성화되어 다음 대화로 넘어갈 수 없다(슬라이더 점수만 받고 근거를 생략하는 UX 지양). 응답은 `session.checkpoints[]`에 누적 저장
- **조직화 — 마인드맵 직접 조작 위젯(원리2·8)** — 빠른 버튼으로 마인드맵을 요청하면 AI는 중심 낱말 1개 + 후보 낱말(지원강도 높음 4~5개/보통 3~4개/낮음 2~3개)만 주고, 순서·위계를 암시하지 않도록 각도를 무작위로 흔들어 흩뿌려 배치한다. 이후 구조화는 전부 학습자가 SVG 캔버스 위에서 직접 함: 낱말을 드래그로 옮기기, “연결선 긋기”를 켜고 낱말 두 개를 차례로 눌러 선 잇기, 선 가운데 이름표를 눌러 관계 이름 붙이기, “+ 낱말 추가”/“선택한 낱말 지우기”로 노드 추가·삭제. AI는 관계·구조에 전혀 관여하지 않고, 완성된 마인드맵(`nodes`/`edges`)은 세션에 저장됨
- **나머지 3개 전략(시연·정교화·비판적 사고)과 조직화의 다른 2개 형식(도표/표, 다이어그램)은 이번 버전에 구현하지 않고 설계 방향만 정리**(다음 버전 예정): 시연은 원문을 가려 스스로 인출한 뒤에만 자기 채점 비교를 보여주는 “가림 인출” 방식, 정교화는 “이거 어디서 본 것 같아?” 트리거로 학습자가 직접 쓴 연결을 사이드 태그로 누적하는 방식, 비판적 사고는 동의/재검토 필요/반박 3지 선택(재검토·반박은 근거 필수)에 AI가 가끔 일부러 허점 있는 답을 주는 방식, 도표(표)는 AI가 행 이름만 채우고 열·칸은 학습자가 채우는 방식, 다이어그램(순서·인과)은 AI가 순서 없는 카드만 주고 드래그 재배열·화살표 방향·화살표 이름을 학습자가 정하는 방식을 검토 중

### v9에서 바뀐 점 (역할 분담 혼선·페이딩 비가시성·체크포인트 간격·목표 표시 개선)
실사용 중 나온 4가지 지적을 반영: 과업 분담이 너무 뭉뚱그려져 있다, "AI 힌트 크기"와 "역할 분담"이 뭐가 다른지 모르겠다, 비계가 정말 줄어드는지 눈에 안 보인다, 체크포인트 간격을 선생님이 숫자로 미리 정하는 게 부자연스럽다, 성취기준·목표 문장이 헤더에서 잘려 보인다.
- **과업 분담을 준비·탐구·마무리 단계로 세분화(원리5)** — 기존 4개뿐이던 이동 가능 블록을 9개(사전지식 질문하기·목표 구체화·개념 설명·예시 들기·힌트 주기·내 답 확인·다음 질문 정하기·틀린 부분 짚기·요약)로 늘리고, 항상 학습자 몫인 잠금 블록도 3개→4개로 늘려 “개념 연결 짓기(정교화)”를 추가(AI가 연결을 대신 만들어주면 안 된다는 원리2 원칙을 과업 블록에도 명시). 시작 화면에 준비/탐구/마무리로 묶어서 표시
- **“AI 힌트 크기”와 “역할 분담” 중복 제거(원리1·5)** — 두 슬라이더가 사실상 같은 축(“얼마나 도와줄지”)을 가리켜 구별이 안 된다는 지적을 그대로 반영해, 역할 분담 슬라이더(힌트~첨삭)를 없앴다. “얼마나 자세히 힌트를 줄지”는 원리1의 AI 힌트 크기(자동 페이딩)가, “그 일 자체를 누가 할지”는 원리5의 과업 블록이 맡아 역할이 겹치지 않게 정리
- **페이딩이 실제로 보이는 단계 표시 바(원리1)** — 대화창 헤더 바로 아래 “많이 → 보통 → 조금” 3단계 바를 상시 표시. 지나온 단계는 체크(✓) 표시로 남고 지금 단계가 강조돼 페이딩이 실제로 진행 중인지 한눈에 확인 가능. 자동으로 줄어드는 순간엔 바가 잠깐 노랗게 깜빡여 “방금 바뀌었다”는 것도 알려줌
- **이해도 체크포인트를 완전 적응형으로(원리9)** — 선생님이 미리 숫자로 정하던 “체크포인트 간격” 설정을 없애고, AI가 대화 신호로 그때그때 판별하게 바꿈: 지원강도에 연동한 기본 주기(서툴수록 자주) 위에 “잘 모르겠어요” 판단·“막혔어요”·공부 방법 변경처럼 이해가 흔들렸다는 신호가 잡히면 다음 AI 응답 직후 곧바로 체크포인트를 앞당겨 띄움
- **성취기준·목표를 줄이지 않고 항상 표시(원리4)** — 대화창 헤더 아래 성취기준 전체 문장(교과·영역·학년 포함)과 학습목표를 그대로 보여주는 박스 추가(예전엔 헤더 한 줄에 40자로 잘려 “…”로 표시됐음)

### v10에서 바뀐 점 (AI 계획 유출 방어, 과목별 소재 구체화, 산출물 피드백)
실사용 캡처로 확인된 3가지 문제를 반영: AI가 학습자에게 직접 말하지 않고 다른 교사에게 설명하듯 “(학습자가 ~하도록 유도)”·“만약 (1) 선택 시: …” 같은 자기 계획·조건분기를 그대로 출력하는 현상, 인지전략이 과목과 무관하게 똑같이 적용되는 문제, 학습자가 마인드맵·드릴·체크리스트 같은 산출물을 직접 완성해도 AI가 그에 대해 아무 피드백을 안 주는 문제.
- **AI 계획 유출 방어(원리2)** — 시스템 프롬프트에 “직접 화법 규칙”을 새로 명시(“당신은 지금 이 학습자와 1:1로 직접 대화하고 있다 — 다른 선생님에게 설명하듯 쓰지 마라”)하고, `hasMetaLeak()`로 이런 패턴을 감지하면 번호 목록 유출(`hasListDump`)과 동일하게 한 번 재시도. 그래도 남아있으면 방어적 필터 `stripMetaLeak()`가 그 줄만 걸러내고 실제 대화 문장만 남김
- **반복되는 “너는 어떻게 생각해?” 개선** — 목록 유출을 잘라낸 뒤 붙이던 고정 문구가 상황과 무관하게 반복돼 “뜬금없다”는 지적을 반영. 이미 질문으로 끝난 문장엔 중복으로 덧붙이지 않고, 그 외에는 지금 고른 인지전략의 구체적인 다음 행동(예: “중요한 낱말을 3번 소리 내어 말해보기, 지금 바로 해볼까?”)을 붙이도록 `stripTaskDump()`를 확장
- **인지전략의 과목별 소재 구체화(원리8)** — 시연·정교화 등 전략 자체는 과목 공통이지만 “무엇을” 반복·예시로 들지는 과목마다 달라야 한다는 지적을 반영, “방법대로 해보기” 지시에 지금 과목에 맞는 소재로 바꿔 제시하라는 지침을 명시적으로 추가(영어=철자·문장, 수학=풀이 순서·검산, 사회·과학=개념·사례)
- **학습자 산출물에 대한 AI 피드백(원리10)** — 마인드맵·드릴(반복 연습 체크)·체크리스트(아는지 확인)처럼 학습자가 직접 완성하는 산출물에 “🔍 다 했어요 — AI한테 보여주기” 버튼을 추가. 누르면 AI가 그 결과 내용을 보고 잘한 점 1가지+다시 생각해볼 점 1가지를 되짚어 묻되, 맞다/틀리다는 단정하지 않음(표·비교·순서 카드는 AI가 만든 것을 학습자가 판단하는 구조라 원리10 판단하기로 이미 커버됨)

### v11에서 바뀐 점 (성취기준 자동 매칭, 혼자 풀어보기 표시 버그, 이해도 적응 루프, 성찰 자료 총망라)
실사용 피드백 7가지를 반영: 성취기준을 학생이 목록에서 고르는 게 부자연스럽다, 잔여물 확인(혼자 풀어보기)이 안 되는 것 같다, 성찰이 빈 칸 글쓰기로 끝난다, 전반적으로 더 쉬운 낱말이 필요하다, 인지전략 선택 후 “지금 바로 해볼까?”가 반복된다, 이해도가 정확히 무엇에 쓰이는지 안 보인다, 대화 중 쌓인 정보가 되짚기·대시보드에 다 안 보인다.
- **성취기준을 학생 자유 서술로 자동 매칭(원리4)** — 세션 시작 화면에서 과목·단원을 직접 고르는 대신 “오늘 공부하고 싶은 것”을 자유 서술로 받는다. 학년군 안 모든 성취기준의 이름·낱말(`kw`)과 겹치는 정도로 1차 후보 30개를 추리고, 그중 가장 맞는 것 하나를 AI가 고른다(실패해도 낱말 점수 1위 후보로 자동 대체). 기존 “직접 과목·단원 고르기”는 접이식 메뉴로 남겨 안전망으로 유지(자동 매칭이 틀렸을 때 되돌릴 수 있음)
- **핵심개념·내용요소 그라운딩(원리4·6)** — `gen_curriculum.mjs`가 원본 데이터셋(`greatsong/k-curriculum-2022`)의 `explanation`(교육과정 공식 해설) · `keywords` 필드를 `curriculum_standards.js`에 `concept`/`kw`로 함께 담도록 확장(1,491건 재생성, 768KB→786KB). 매칭된 성취기준의 `concept`을 시스템 프롬프트에 실어, 모든 응답이 그 학년의 그 내용 범위를 벗어나지 않도록 함
- **학년별 응답 수준 분리(원리4)** — 예전엔 학년 선택과 무관하게 시스템 프롬프트가 항상 “초등 3학년 수준”으로 고정돼 있어 고등학생에게도 유아적으로 답하는 문제가 있었음. `gradeLangLevel()`을 추가해 초3-4/초5-6/중학교/고등학교 구간별로 다른 말 수준 규칙을 쓰게 함
- **“혼자 풀어보기(잔여물 확인)” 진입 버튼이 항상 숨겨져 있던 버그 수정(원리13)** — 되짚기 화면의 `#residual-cue` 안내 박스가 `enterReflect()`에서 매번 무조건 `hidden=true`로 재설정되어, 실제로는 한 번도 학습자에게 보인 적이 없었다(버튼(`#btn-goto-residual`) 자체는 정상 동작했지만 도달할 방법이 없었음 — “구현이 안 된 것 같다”는 지적의 실제 원인). 문구도 “보통 3~7일 뒤 알림이 와요”처럼 실제로 존재하지 않는 자동 알림 기능을 약속하던 것을 “지금 해도 되고 내 학습터에서 나중에 다시 할 수 있다”로 정정
- **내 학습터에 공부 전·후 비교 위젯 추가(원리13)** — 그동안 사전 진단 점수(`prior.diagScore`)와 혼자 풀어보기 점수(`residual.postScore`)의 비교가 되짚기 화면에서만 보이고 누적 대시보드엔 전혀 없었음. 지난 세션들의 전·후 점수를 나란히 보여주는 위젯과, 가장 최근 세션이 아직 혼자 풀어보기 전이면 대시보드에서 바로 이어갈 수 있는 버튼을 추가
- **성찰에 “질문 하나 받기” — AI 도움자료의 범위를 좁게 정의(원리2·11·12)** — “성찰이 빈 칸에 글쓰기로만 끝나도 되는가”라는 질문에 대해, AI가 성찰문을 대신 써주거나 요약해주는 기능은 넣지 않기로 하고, 대신 막막할 때만 누르는 “질문 하나 받기” 버튼을 추가했다. 이 버튼은 이번 대화에서 학습자가 실제로 한 말들을 근거로 “그때 왜 그렇게 했는지” 되묻는 질문 1개만 만들어 보여주고, 성찰문 작성은 끝까지 학습자가 빈 칸에 직접 쓴다(원리2 최종판단 보존과 충돌하지 않도록 범위를 의도적으로 좁게 제한)
- **“지금 바로 해볼까?”가 매번 반복되던 문제 수정(원리8·9)** — 원인은 두 가지였다. ① AI가 번호 목록으로 정리해버려 안전 문구로 대체될 때, 그 고정 문구 자체가 항상 “…, 지금 바로 해볼까?”로 끝나는 허락 구하기 형태였다(`stripTaskDump`의 `fallbackTail`). 허락을 구하지 않고 바로 시켜보는 직접 지시 문구 여러 개 중 무작위로 고르도록 수정. ② “방법대로 해보기(apply)” 단계 지시 자체에도 “~해볼까?”로 묻지 말고 “이번엔 ~를 해보자”처럼 단정적으로 과업을 내라는 규칙을 명시적으로 추가
- **이해도 체크포인트 점수를 실제로 쓰이게 함(원리9)** — 그동안 1~5점 확신도 점수는 `session.checkpoints[]`에 기록만 되고 대화 흐름에 전혀 반영되지 않았다. 이제 낮은 점수(1~2)를 표시하면 다음 AI 응답이 “더 쉬운 낱말과 예시로 다시 설명하라”는 지시를 한 번 받아 실제로 반영된다(적응 루프를 닫음). 되짚기 화면에 체크포인트 점수 추이를 보여주는 **꺾은선 그래프**를 새로 추가하고, 체크포인트·사전 진단·메타인지 점검 카드마다 “이 점수가 무엇에 쓰이는지”를 짧게 설명하는 문구를 붙임
- **대화 중 쌓인 정보를 되짚기 화면에 총망라(원리3·7·11)** — 그동안 계산·저장은 됐지만 어디에도 보이지 않던 것들을 되짚기(가) 화면에 모아 보여줌: 이해도 체크포인트 추이(그래프), 방법을 바꾼 기록(`strategyChangeLog`, 바꾼 이유 포함), 이번 공부에서 만든 표·마인드맵·비교·드릴·체크리스트 등 구조화 산출물 목록, 과업 분담(AI가 맡았던 일 vs 내가 맡았던 일) 요약
- **`smoke2.mjs` 관련 참고** — 이 통합 테스트는 v6 이전 구조(단일 전략 선택, 별도 사전진단 퀴즈, 과업 블록 없음 등)를 기준으로 작성되어 v6~v11의 변경사항(과업 블록, 다중 전략, 체크포인트, 마인드맵 위젯, 4단계 조정 순환, 성찰 가·나 분리, 성취기준 자동 매칭 등)을 검증하지 못한다. 이번 변경은 문법 검사(`node --check`) · HTML `id` 참조 전수 대조 · 신규 순수 로직 함수(`topStdCandidates`/`gradeLangLevel`/`tokenizeKo`) 단위 테스트로 검증했으며, 전체 사용자 흐름을 다시 검증하려면 `smoke2.mjs`를 현재 구조에 맞게 재작성해야 한다

### v12에서 바뀐 점 (Google Sheets 백엔드, 지난 기록 클릭 버그, 과목별 어포던스, 과목 선택·복수 성취기준)
실사용 피드백 6가지를 반영: 내 학습터의 지난 공부 기록을 눌러도 반응이 없다, 백엔드를 Redis에서 구글시트로 옮기고 싶다, 영어·수학은 다른 과목과 다른 어포던스(말하기·듣기, 손글씨)가 필요하다, 대화 전에 과목을 고르는 란이 있으면 좋겠다, 성취기준이 꼭 1개여야 하냐(여러 개일 수도), 성취기준별 내용요소도 메타데이터로 있어야 한다.
- **“지난 공부 기록” 클릭 버그 수정(원리3)** — `.sess-item`에 클릭 이벤트 리스너 자체가 없어서 눌러도 아무 반응이 없었다(실사용 보고로 확인). 눌렀을 때 그 세션의 성취기준·목표·고른 방법과 이유·점수·대화 내용·돌아보기 서술·과업 분담을 읽기 전용으로 다시 볼 수 있는 상세보기 모달(`openSessDetail`)을 추가. 공부 전·후 비교 목록의 항목도 같은 방식으로 클릭할 수 있게 함
- **백엔드를 Redis → Google Sheets로 이전** — `api/_store.js`를 서비스 계정 JWT(RS256, `node:crypto`만 사용 — 새 npm 의존성 없음) 기반 Sheets REST API 호출로 전면 재작성했다. `kvGet`/`kvSet`/`kvSetNX`/`kvDel`이라는 기존 key-value 인터페이스는 그대로 유지해 `api/auth.js`·`api/data.js`는 한 줄도 바꾸지 않았다. 계정은 **Users** 탭(닉네임당 1행), 학습 데이터는 **Sessions** 탭(**세션 1개 = 행 1개**, 프런트가 세션 배열을 통째로 재전송해도 실제로 바뀐 세션만 다시 씀)에 저장하고, 탭·헤더 행이 없으면 앱이 처음 호출될 때 자동으로 만든다(요청사항: “탭별 헤더를 알아서 만들어달라”). 성취기준 데이터(1,491건)는 정적 참고자료라 시트로 옮기지 않고 그대로 앱에 내장하기로 했다(매 세션 시작마다 시트에서 불러오면 느려지고 API 한도에도 더 민감해짐 — README에 이 판단 이유를 남김). `redis` npm 의존성 제거, 설정 방법은 README “Google Sheets 백엔드 설정” 절 참고
- **과목별 어포던스 차별화(원리8)** — 국어·사회·과학은 대화(주지주의적 어포던스)로 충분하다고 보고 그대로 두되, 영어는 브라우저 내장 음성인식으로 **🎤 말해서 입력하기**와 브라우저 내장 TTS로 AI 말풍선을 **🔊 영어 발음으로 들어보기**를 추가했다(둘 다 별도 API 키 불필요). 수학은 **✍️ 손글씨로 풀기** 캔버스를 추가 — 손으로 쓴 풀이를 Google Cloud Vision(`DOCUMENT_TEXT_DETECTION`)으로 텍스트로 바꾸고, 곧바로 보내지 않고 편집 칸에 먼저 보여줘 학습자가 고친 뒤 입력창에 넣는다(OCR도 틀릴 수 있으니 최종 확인은 항상 학습자 몫 — 원리2). 새 엔드포인트 `api/ocr.js`는 Sheets와 같은 서비스 계정 자격증명을 재사용한다(Cloud Vision API만 추가로 사용 설정하면 됨)
- **대화 전 과목 선택 란 추가(원리4)** — 세션 시작 화면에 학년 옆에 항상 보이는 과목 란을 추가했다. 비워 두면(“전체 과목에서 찾기”) 학년군 전체에서 자동 매칭하고, 과목을 고르면 그 과목 안에서만 찾아 매칭이 더 정확해진다
- **성취기준 복수 선택(원리4)** — “성취기준이 꼭 1개여야 하냐”는 질문에, 과목을 넘나드는 공부라면 여러 개일 수 있다고 보고 기본 1개 위에 **관련 성취기준을 최대 2개까지 더 찾아 추가**할 수 있게 했다(`session.ctx.extraStds`). 추가한 성취기준의 핵심개념도 시스템 프롬프트에 실려, 원래 성취기준과 자연스럽게 연결하도록 유도한다(억지로 매 턴 끼워 넣지는 않음). 대화창 헤더·상세보기에도 함께 표시
- **성취기준별 내용요소 메타데이터** — v11에서 이미 `curriculum_standards.js`에 `concept`(교육과정 공식 해설)·`kw`(핵심 낱말)를 담아 두었고, 이번에 추가한 성취기준 복수 선택에도 그대로 재사용된다(새 필드 추가 없음)

### v13에서 바뀐 점 (준비 대화 가·나·다·라 재구성, 과업 분담 정밀화, 성찰 화면 재구성)
실사용 피드백 9가지를 반영: AI-인간 과업 위임 범위가 여전히 어색하고 낱말도 어렵다, 성취기준을 1~3개 한 번에 자동으로 골라달라, 힌트 크기 고르면 과업 분담도 꾸러미로 세팅되면 좋겠다, 혼자 풀어보기는 대화 직후 성찰 단계에서만 해야 한다, 대시보드·성찰 시각화가 부족하다, 인지전략 고르기 전에 내 수준 정보를 보여줘야 한다, 준비 대화를 원리6·7·8·9 순서(가·나·다·라)로 재구성해달라, 판단하기 결과를 성찰에서 묶어 보여줘야 한다, 성찰 대화내역을 세로 목록으로 바꾸고 태깅 개수 제한을 없애야 한다.
- **과업 분담 재정밀화(원리5)** — "새로 배우는 내용 설명하기"조차 학생이 아직 모르는 내용이라 스스로 할 수 없다는 지적을 반영해, 고정 자리를 **항상 AI가 하는 일 / 항상 내가 하는 일** 둘로 나누고 이 블록을 AI 쪽에 고정했다. 이동 가능한 "회색지대" 블록은 5개로 좁아졌고, ①에서 고른 AI 힌트 크기(많이/보통/조금)에 맞춰 `SUPPORT_PRESET`으로 이 5개의 AI/내 담당이 **자동으로 한 번에 세팅**된다(그래도 블록을 눌러 자유롭게 옮길 수 있음). 시작 화면에 "이 5개는 회색지대, 나머지 둘은 고정"임을 짧게 설명하는 문구를 추가
- **성취기준 자동 매칭을 1~3개로 통합(원리4)** — "따로 더 찾기" 2단계였던 흐름을, 자유 서술 한 번으로 AI가 학년군 후보 중 가장 잘 맞는 것을 **1~3개까지 한꺼번에** 고르도록 통합했다(과목을 넘나드는 내용이면 여러 개, 아니면 1개). "오늘 나의 목표" 입력란은 "오늘 공부하고 싶은 것"과 중복이라는 지적을 받아 없앴다 — 목표는 원래도 준비 대화 첫 턴에서 학습자 답을 받아 `session.goal`에 채워지므로 그 경로 하나로 통일
- **"혼자 풀어보기"는 성찰 단계 전용으로 정리(원리13)** — v11에서 대시보드에 추가했던 "이어서 혼자 풀어보기" 시작 버튼을 없앴다. 대시보드는 지난 결과를 **보여주기만** 하고(사전·사후 점수 꺾은선 그래프 추가), 새로 시작하는 곳은 대화를 마친 뒤의 되짚기 화면 하나로 정리했다
- **준비 대화를 원리6·7·8 순서(가·나·다)로 재구성** — 목표를 정하면 곧바로 **가. 아는 것 확인**(원리6) 카드가 뜬다: 기억해내기·예시 들기·자기 말로 설명하기·다른 상황에 적용하기 등 서로 다른 방식의 짧은 문항 4개(시험이 아니라고 명시, 부담 없이)에 답하면 AI가 0~100점으로 채점한다(잔여물 확인의 사후 진단과 같은 채점 기준). 이어서 전체 자신감(1~5)을 고르고, **나. 스스로 점검**(원리7)에서는 먼저 "평소 이 내용은 보통 어떻게 공부해?" 한 줄을 받은 뒤 기존 이해·전략·연결 스캐폴딩을 그대로 진행한다. **다. 방법 정하기**(원리8)에서는 카드를 보여주기 전에 가·나 단계에서 나온 점수를 요약 패널로 먼저 보여주고("인지전략 선택이 학습자의 메타인지·교과지식과 맞아야 하지 않냐"는 지적 반영, 참고용·최종판단은 학습자), 전략 카드의 영문 이론명(Rehearsal 등)은 빼서 더 친숙하게 다듬었다. 상단 진행 표시 바도 이 가·나·다 이름으로 바꿈
- **라 단계(원리9) 점검·조정 질문을 진단적으로 강화** — 점검(check) 질문이 "왜 그렇게 생각했어?"에 그치지 않고, 아직 헷갈리는 부분이 있는지·방금 쓴 방법이 실제로 도움이 됐는지·안 맞았다면 어디서 어떻게 걸렸는지(오류 유형)를 학습자 스스로 짚어보게 지시를 구체화했다. 조정(adjust) 단계에서도 안 맞았다는 신호가 보였으면 방법을 바꿀 기회라는 걸 짧게 짚어주도록 함(대신 정하지는 않음)
- **되짚기 화면 판단 모아보기(원리10) + 화면 재구성(원리11)** — 대화 중 AI 말마다 개별로 했던 "판단하기"(좋아요/잘 모르겠어요/다른 생각)를 한 번에 묶어 다시 보는 목록을 추가했다. 대화내역을 가로 스크롤 카드열 대신 **세로 목록(좌측 칸, 우측엔 그래프·기록·서술칸)**으로 바꾸고, "각각 최대 3개"였던 태깅 개수 제한을 없애 원하는 만큼 자유롭게 고를 수 있게 했다(최소 하나만 고르면 다음으로 진행 가능)
- **대시보드 시각화 보강** — 사전 진단 vs 혼자 풀어보기 점수를 회차별 꺾은선 그래프로 추가해 텍스트 목록만으로는 안 보이던 추이를 보여준다

### v14에서 바뀐 점 (목표 절차 제거, 대화·평가 동시 노출 방지, 전략 선택 안내 쉬운 말로)
실사용 피드백 5가지 반영: 손글씨 인식이 Vision API 오류로 안 됨, 목표 말하기 절차를 없애고 가·나·다·라(활성화-메타인지점검-방법정해서과제-피드백받고수정, 다·라는 왔다갔다) 순서로만 가라, 대화 응답과 이해도 체크·전략 선택 카드가 동시에 뜨면 학생이 헷갈린다, "지금까지 나온 내 정보"를 더 쉬운 말로, 전략 선택 시 무엇이 도드라졌는지 추천 안내가 있으면 좋겠다(교육적으로 괜찮은지도 확인).
- **손글씨 인식 Vision API 오류의 원인** — 코드 문제가 아니라 **연결된 Google Cloud 프로젝트에 결제(billing)가 연결되지 않아** 생기는 오류였다(`This API method requires billing to be enabled`). Cloud Vision API는 매달 무료 사용량이 있어도 프로젝트에 결제 수단이 걸려 있어야 호출이 열린다 — Google Cloud Console → 결제(Billing) → 이 프로젝트에 결제 계정 연결에서 설정해야 한다(코드로 우회할 수 없음, README에 안내 추가)
- **"목표 말하기" 절차 완전 제거(원리4)** — v13에서 시작 화면의 "오늘 나의 목표" 입력란은 없앴지만 대화 첫 턴에서 "오늘 이걸로 뭘 하고 싶어?"를 또 물었던 게 여전히 중복이라는 지적. 이제 시작 화면에 적은 "오늘 공부하고 싶은 것"을 그대로 `session.goal`로 쓰고, `advancePrep()`이 인사 후 **묻지 않고 곧바로 가 단계(아는 것 확인)로** 넘어간다. 진행 표시 바에서도 "목표 정하기" 노드를 없앴다
- **가·나·다·라 순서 재확인 + 다·라 왔다갔다 표시(원리8·9)** — 탐구 대화의 순환 절차 표시를 "①질문→②시행→③평가→④조정"에서 **"다(질문받기+방법대로 과제하기) / 라(AI 피드백받기+점검하고 수정하기)"** 두 덩어리 이름으로 바꿔, 다·라가 계속 왔다갔다한다는 걸 이름 그대로 보여준다(내부 4신호 로직은 그대로, 표시만 이번 요청에 맞게 재편)
- **대화 응답과 구조화 카드가 동시에 뜨는 문제 수정(원리1·9)** — 이해도 체크포인트가 곧 뜰 차례라는 걸 `checkpointWillFire()`로 미리 계산해서, 그 턴의 AI 응답 자체는 **새 질문 없이 마무리 문장으로만** 답하도록 지시를 추가했다. 예전엔 AI가 대화 질문으로 끝맺는 것과 동시에 체크포인트 카드가 뜨는 바람에, 대화에 답해야 하는지 카드에 답해야 하는지 헷갈릴 수 있었다(실사용 지적으로 확인)
- **"지금까지 나온 내 정보" 패널을 쉬운 말로 + 참고 추천 추가(원리2·8)** — 점수를 그대로 보여주던 것("70점")을 `scoreBand()`로 "아직 낯설어요/조금씩 알아가고 있어요/꽤 알아요/잘 알아요" 같은 말로 바꿨다. "전략 선택 시 무엇이 도드라졌을 때 추천하는지 안내가 없다"는 질문에 대한 답: 교육적으로 문제되지 않는 수준(정답을 대신 정해주지 않고 "~일 수도 있으니 참고해봐" 정도의 약한 추천, 이미 있는 `suggestStrategyCheck`의 대안 제안과 같은 결)으로 판단해 추가했다 — 가장 낮은 항목 하나를 짚어 관련 전략을 참고 문장으로 안내하고("💡 참고: 아직 헷갈리는 부분이 있을 수 있어요 — 🎯 내가 아는지 확인하기가 도움될 수 있어요"), 모든 점수가 무난하면 격려 문구로 대체한다. 최종 선택은 항상 학습자가 한다는 문구를 바로 옆에 함께 둠

### v15에서 바뀐 점 (AI 계획유출·표 대행 재발 방지, 되짚기→혼자풀어보기 재회귀 버그, 전략 순차 진행, 절차 통합 표시)
실사용 피드백 8가지 + 중간 제보 1건을 반영: AI가 "(학습자가 2를 선택함)" 같은 지시문을 문장 안에 섞어 계속 새어 나옴, 나 단계에서 스캐폴딩을 다 안 해도 다음으로 넘어갈 수 있음, AI 도움 크기가 안 줄어듦, 절차 표시를 대화 전체 중심으로, 정리 버튼이 조직화 전략일 때만 나오는지 확인, 표로 정리하기를 누르면 AI가 답을 다 줘버림, 마인드맵 피드백 요청 시 AI가 내용을 무시하고 다시 설명해달라고 함, 복수 전략을 순서대로 하나씩 끝내고 다음으로 넘어가면 좋겠음. 그리고 작업 중간에 "되짚기 뒤에 혼자 풀어보기가 또 안 보인다"는 제보.
- **되짚기 → 혼자 풀어보기 안내가 다시 안 보이던 버그(원리13)** — v11에서 고쳤다고 기록했던 바로 그 버그가 실은 절반만 고쳐져 있었다. HTML의 `hidden` 속성은 지웠지만, `enterReflect()` 안에 `$('#residual-cue').hidden = true;`가 그대로 남아 있어서 되짚기 화면을 그릴 때마다 매번 다시 강제로 숨기고 있었다(부모 요소가 이미 올바르게 보이고 숨기고 있어서 이 줄은 원래 필요도 없었다). 그 줄을 완전히 삭제
- **AI 지시문 유출 탐지·제거를 대폭 강화(원리2)** — "(학습자가 2를 선택함) 2라, 알겠어!"처럼 지시문이 줄 전체가 아니라 실제 대화 문장 안에 끼어 있는 경우, `hasMetaLeak`/`stripMetaLeak`가 통째로 못 잡고 있었다(줄 전체 일치만 검사). 문장 안에 낀 조각도 잡도록 패턴을 넓히고(선택함·답변 후·보여주며 등 추가), 같은 메시지에 "(학습자…)"류가 2번 이상 나오면 낱말과 무관하게 구조만으로도 잡는다. 시스템 프롬프트의 "직접 화법 규칙"에도 "학습자가 아직 답 안 했는데 답했다고 치고 여러 턴을 미리 시뮬레이션하지 말라"는 문구를 구체적으로 추가
- **자유 텍스트로 "정리해줘"라고 하면 마크다운 표를 그대로 만들어 버리는 문제 수정** — 위 지시문 유출을 추적하다 발견: 번호 목록(`hasListDump`)만 감지하고 마크다운 파이프 표(`| … | … |`)는 전혀 감지하지 못해, 자유 텍스트 요청에는 재시도가 걸리지 않고 그대로 나갔다(과업 대행 금지·마크다운 금지 둘 다 어김). `hasTableDump()`를 추가해 같은 재시도 파이프라인에 태우고, `stripTaskDump()`도 표 시작 지점에서 자르도록 확장
- **나 단계 스캐폴딩을 다 안 해도 "다음"이 눌리던 버그(원리7)** — `meta` 단계에 들어서자마자(이해·전략·연결 스캐폴딩 3개를 묻기도 전에) "다음" 버튼이 바로 나타나 있었다. 이제 `meta.step`이 `SCAFFOLD_ORDER.length`에 이른 뒤(3개 다 묻고 답까지 받은 뒤)에만 버튼이 보인다
- **AI 도움 크기가 안 줄어드는 문제 보강(원리1)** — 기존엔 대화 중 "판단하기"에서 좋아요를 연달아 2번 눌러야만(선택적 신호) 줄었는데, 그 클릭을 잘 안 하면 아무리 잘 이해해도 안 줄었다. 이해도 체크포인트(누구나 매번 답해야 하는 필수 신호)도 높은 점수(4~5)가 연달아 2번 나오면 같은 방식으로 줄어들도록 두 번째 경로를 추가(`cpHighStreak`)
- **"표로 정리하기"를 누르면 AI가 표를 다 채워 줘버리는 문제 수정(원리2·8)** — `STRUCT_SCHEMAS`의 table·compare·chain 세 스키마가 전부 "AI가 내용을 완성해서 준다"로 돼 있었다(마인드맵만 "후보만 주고 배치는 학습자가" 원칙을 따르고 있었음). 셀에 무엇을 넣을지·비교 내용·순서는 AI가 정하지 않고 재료(후보)만 주도록 다시 쓰고, 렌더링도 학습자가 직접 입력·클릭으로 채우는 위젯으로 바꿨다 — 표는 빈 칸에 직접 타이핑, 비교는 두 칸에 직접 서술, 순서 사슬은 뒤섞인 후보를 순서대로 눌러 담는 방식
- **마인드맵 등 완성한 산출물에 AI 피드백을 요청해도 무시하고 다시 설명해달라고 하는 문제 완화** — `reviewStruct()`가 실제 내용을 이미 지시문에 담아 보내는데도 모델이 최근 대화 흐름(바로 앞의 표 대행 실패로 오염된 맥락)을 따라 다시 설명을 요구하는 경우가 있었다. 위 표 대행 버그를 고쳐 오염 자체를 줄였고, 지시문에도 "이미 다 알고 있으니 다시 설명해달라고 요청하지 마라"를 못 박아 회피 경로를 막았다
- **복수 전략 선택 시 순서대로 하나씩 끝내고 다음으로(원리8)** — 예전엔 apply 턴마다 전략을 그냥 돌아가며 바꿔서, 한 전략을 제대로 끝내지도 못하고 다음 전략으로 넘어가곤 했다. `session.stratDone`을 추가해 "다 했어요" 리뷰를 받은 전략만 완료로 표시하고, `currentApplyStrat()`이 아직 안 끝난 전략을 순서대로 고정해서 계속 쓰다가, 다 끝나면 그때부터 다시 돌려가며 연습하게 바꿨다
- **절차 표시를 대화 전체 중심으로 통합(원리4·8·9)** — 준비 단계(가·나·다)일 때만 보이던 띠와 탐구 단계(라)일 때만 보이던 띠가 서로 다른 UI라 연결이 안 보인다는 지적. 가→나→다→라 전체를 하나의 항상 보이는 띠로 합치고, 라 단계에 들어서면 그 아래에 다·라의 세부(질문받기/과제하기/피드백받기/점검수정)만 보조로 붙는다
- **참고: "표·마인드맵 정리 버튼이 조직화 때만 보이나?" 질문에 대한 답** — 아니다. `currentStructs()`가 **지금 고른 모든 전략**의 산출물 버튼을 종류별로 중복 없이 모아 보여준다(조직화=표+마인드맵, 이해 점검=체크리스트 등). 조직화+이해 점검을 함께 고르면 표·마인드맵·체크리스트 3개가 같이 보이는 게 정상 동작이었다

### v16에서 바뀐 점 (나 단계 진행 버그, 성찰 화면 정리, 과업 분담 재검토)
다른 컴퓨터에서 v11~v15 작업을 반영한 뒤 받은 3가지 지적: 나(스스로 점검) 단계에서 다(방법 정하기)로 안 넘어간다, 성찰 화면 정보가 산발적이다, AI/학습자 과업 경계가 여전히 불명확한 곳이 있다.
- **나 → 다 단계 진행 버그(원리7)** — 이해·전략·연결 스캐폴딩 3개에 모두 답해도 `[다음으로]` 버튼이 계속 안 보이는 버그. 원인은 `session.meta.step`이 문턱(`SCAFFOLD_ORDER.length`)에 닿는 시점(`sendChat()`의 `meta` 분기)과, 그 값을 읽어 버튼의 `hidden`을 정하는 `paintPhase()`가 실제로 호출되는 시점이 어긋나 있었던 것 — 그 분기는 `ai()`만 호출했는데 `ai()`는 `renderStream()`만 부르고 `paintPhase()`는 부르지 않는다. 값은 이미 바뀌었는데 화면(버튼의 hidden 속성)이 그 값을 다시 읽어 보질 않으니, 학습자 입장에선 "분명 다 답했는데 안 넘어간다"로 보였다. 세 번째 스캐폴딩 답을 처리하는 분기 끝에 `paintPhase()` 호출을 추가해 그 자리에서 즉시 버튼이 나타나게 고쳤다
- **성찰(되짚기) 화면 정보 정리(원리11)** — 같은 정보(내가 생각/AI에게 맡김 개수)가 tag-counter 글자·도넛 차트·박스 안 metric 3곳에 중복 표시되고, 박스 제목과 실제 내용이 안 맞는 곳도 있어(예: "AI 말에 내가 어떻게 표시했나" 제목 아래 실제로는 내 발화 태그 개수가 나옴) 산발적으로 느껴진다는 지적을 반영. 도넛 차트·중복 metric·대화 시작 전에 이미 정해진 과업 분담 로그(성찰 대상이 아니라 설정값이라 이 화면에 안 맞음)를 지우고, 실제로 그 대화에서 있었던 일만 하나의 요약 박스로 모았다. 아무 일도 없었던 항목(방법을 안 바꿨거나 자료를 안 만들었을 때)은 "이번엔 안 했어요" 빈 상태 문구 대신 박스 자체를 숨겨 화면 길이를 줄임
- **과업 분담 재검토(원리2·5)** — "정답 확인은 기본적으로 AI가 하는 일이고, 힌트도 필연적으로 AI 도움을 전제한다 — 여전히 AI/학습자 경계가 불명확하다"는 지적을 계기로 이동 가능 블록 5개를 다시 하나씩 검토했다. `checkwork`("내 답 맞았는지 확인하기")를 "내가"로 옮기면 실제로는 아무도 정답 여부를 확인해 주지 않는 상태가 된다는 걸 확인 — 아직 배우는 중인 내용이라 학습자에게는 판단 근거(정답지)가 없고 AI 없이는 검증 자체가 불가능하다(v13에서 "새로 배우는 내용 설명하기"를 고정했던 것과 같은 이유). `connect_make`·`self_judge`와 달리 "학습자가 대신 하는 버전"이 아예 성립하지 않아, checkwork도 "항상 AI" 쪽으로 고정했다. 반대로 `error_find`는 정답을 몰라도 "내 풀이 안에서 앞뒤가 안 맞는 곳을 스스로 짚어보는" 비판적 사고 활동(critical 전략의 반례 찾기와 동일한 성격)이라 학습자 혼자서도 시도할 수 있어 그대로 이동 가능 블록에 남기되, 최종 확정이 아니라 "먼저 스스로 의심 지점을 찾아보는 것"임을 라벨(🧐 의심 가는 부분 먼저 찾아보기)에서 드러냈다. 이동 가능 블록 5개→4개

### v17에서 바뀐 점 (탐구 대화 분기 오류 수정, 산출물 리뷰 2회제, 전략 전환 카드 즉시 제안, 잔여물 3점 비교)
다른 컴퓨터에서 동시에 진행된 v16 작업과 별개로, 같은 시점에 받은 실사용 피드백 4가지를 반영: AI가 표·마인드맵 같은 산출물을 여전히 못 읽는 것 같다, 복수 전략을 골랐는데 1번 전략만 계속하고 2번으로 안 넘어간다, "점검하고 수정해요"가 실제로 전략을 바꾸는 데 도움이 안 된다, 잔여물(인지적 변화) 비교를 "인지전략 과업 수행 시점 vs 그 이후"로 다시 잡아야 한다. (git merge로 v16과 합침 — index.html은 서로 다른 함수를 건드려 충돌 없이 자동 병합됨)
- **탐구 대화(라 단계) 분기 오류 수정 — 가장 중요한 수정** — v13 즈음 check 단계를 보강하며 실수로 `if/else if` 체인 하나를 둘로 쪼갰다. 그 결과 매 턴마다 **ask·apply 단계에서도 instr이 항상 adjust(조정) 문구로 덮어써지고** 있었다 — 즉 소크라테스식 발문(ask)과 구체적 과업 지시(apply)가 실제로는 거의 나간 적이 없고, "계속 쓸까 바꿀까?" 류 조정 문구가 계속 나가고 있었다. 실사용 캡처에서 반복 관찰된 "AI가 산출물을 무시한다", "맥락과 안 맞는 말을 한다" 류 증상들의 숨은 원인 중 하나로 보인다. 4개 분기를 하나의 `if/else if` 체인으로 합쳐 바로잡았다
- **산출물 리뷰 응답 강화(원리2)** — v15로도 "새 정보를 더 넣어줄게"처럼 일반적인 말로 넘어가는 경우가 남아있었다. 학습자가 실제로 쓴 낱말을 **최소 1개 그대로 언급**하도록 못 박고, 새 내용 추가를 명시적으로 금지. 지시문 유출 탐지에도 "바탕으로"·"완성해" 같은 패턴을 추가
- **복수 전략 순차 진행 — 2회 리뷰제(원리8)** — 같은 산출물을 "다 했어요"로 **두 번째** 보여주면(피드백 받고 한 번 고쳐서 다시 보여준 것으로 봄) 그 전략을 완료 처리하고, AI가 그 자리에서 바로 "이제 다음 방법인 OO로 넘어가자"고 안내하며 새 과업을 낸다. 첫 번째 리뷰에서는 완료 처리하지 않고 고쳐보라는 피드백만 준다
- **"점검하고 수정해요"에서 전략 카드를 즉시 제안(원리9)** — 최근 "막혔어요"·"잘 모르겠어요" 신호가 쌓였으면, adjust 턴에서 헤더 구석의 버튼을 찾아 누르게 하는 대신 **그 자리에서 바로 전략 카드를 다시 띄운다**(`kind:'strategy-pick'` 재사용). 신호가 없으면 예전처럼 가볍게 묻기만 한다. 최종 선택은 항상 학습자
- **잔여물 확인에 3점 비교 추가(원리13)** — "사전 vs 사후"만 비교하던 걸 "사전 진단 → **방법대로 과제를 하던 중(체크포인트 평균, 0~100 환산)** → 사후 진단" 3점 흐름으로 넓혔다. 인지전략 기반 과업을 수행하는 동안의 이해도와, AI 도움 없이 혼자 풀 때의 이해도를 나란히 볼 수 있다

### v18에서 바뀐 점 (수학 수식 인식 보강)
실사용 피드백: "수학 부분이 수식을 제대로 인식 못한다."
- **원인** — Google Cloud Vision은 범용 문서/손글씨 OCR이라, 분수(가로줄 위아래)·지수(위 첨자)·근호처럼 평면이 아니라 **2차원 구조로 읽어야 하는 수식 기호**를 전용 수식 인식 엔진 없이는 원천적으로 잘 못 읽는다. Vision API 설정을 바꾼다고 해결되는 문제가 아니다(Mathpix 같은 전용 수식 OCR은 별도 서비스·키가 필요해 이번엔 범위 밖으로 둠)
- **완화(원리2)** — 이미 연결된 Upstage로 OCR 결과를 한 번 더 보정하는 단계(`refineMathOcr`)를 추가했다: OCR이 읽은 원문을 보여주고 "분수·지수·근호를 평범한 텍스트 표기(3/4, x^2, sqrt(9) 등)로 다시 정리해달라"고 요청한다. 흔한 오독은 어느 정도 나아지지만, 진짜 2차원 구조를 원천적으로 놓친 경우까지 되살리진 못한다 — 그래도 최종 확인·수정은 항상 편집 칸에서 학습자가 한다
- **보조 입력 수단 추가** — 손글씨 인식의 한계를 감안해, 수학 과목일 때 대화창에 **수식 기호 버튼**(／분수, ^지수, √, ×, ÷, π)을 추가해 타이핑으로도 정확하게 넣을 수 있게 했다(손글씨 대신/함께 사용 가능)

### v19에서 바뀐 점 (인지전략 나선형 진행, 대시보드 확장, 잔여물 어포던스 일치, 비판적 검토 실효화)
- **인지전략 나선형(spiral) 진행(원리8·9)** — 복수 전략을 골랐을 때 1번 전략만 계속되고 2번으로 안 넘어가던 문제. 지금까지는 구조화 산출물(표·마인드맵 등)을 "다 했어요"로 2번 보여줘야만 다음 전략으로 넘어갔는데, 그 버튼을 안 쓰면 영영 안 넘어갔다. 이제 대화만으로도 진행된다 — 한 전략으로 시행(apply)→점검(check)→조정(adjust) 한 바퀴를 2번 돌면(=충분히 연습했다고 봄) adjust 턴에서 자동으로 "이 방법은 됐고 다음 방법으로 넘어가자"고 알려주며 새 과업을 낸다. 구조화 산출물 경로(2회 리뷰)는 지름길로 그대로 둔다. 남은 전략이 없으면 기존처럼 "계속 쓸까/바꿀까"를 묻는다.
- **조직화 전략 버튼을 채팅창 안으로(원리2·8)** — "표/마인드맵 버튼이 입력창 옆 도구줄에 있어서 제대로 안 쓰이는 것 같다"는 지적. 지금 방법이 쓰는 산출물 버튼을 AI가 과업을 낸 그 말풍선 안에 바로 붙인다(`structOffer`). 도구줄 버튼은 보조로 남긴다.
- **잔여물(혼자 풀어보기) 문항의 어포던스 일치(원리2·13)** — "표 풀이 과제라면서 왜 빈 텍스트박스만 주냐"는 지적. 탐구 단계에서 조직화(표)·비판적 사고(비교)로 골랐던 학습자에게는, 혼자 풀어보기에서도 그때와 비슷한 입력틀(직접 채우는 표, 좌우 비교 칸)을 준다. 채점은 그대로 텍스트 채점기를 쓴다(입력 위젯이 바뀔 때마다 채점용 문자열로 직렬화).
- **"다른 생각"(비판적 검토)의 즉시 반응(원리10)** — AI 말마다 남기는 판단(좋아요/잘 모르겠어요/다른 생각) 중 좋아요·잘 모르겠어요는 이미 그 자리에서 AI 도움 크기·점검 제안에 반영되는데, "다른 생각"만 되짚기 화면에 쌓아두기만 하고 그 순간엔 아무 일도 안 일어났다(가장 깊은 비판적 사고인데 제일 허무했다는 지적). 이제 남기는 즉시 AI가 그 지적을 실제로 검토해 맞받는 반응을 한다.
- **메인 대시보드 확장(원리3)** — ① 과목별 성취도(사후 진단, 없으면 사전 진단 평균) 위젯 추가. ② "내 생각 vs AI 도움"을 100%로 쪼개는 도넛(이분법적 비율로 보인다는 의견)에서, 우열 없이 각자 횟수를 따로 보여주는 막대 그래프로 바꿈. ③ 버튼을 누르면 지금까지 쌓인 기록(방법 빈도·과목 점수·주도성·막힌 횟수)을 근거로 AI가 짧게 종합 코칭을 해주는 위젯 추가(서열화·단정 금지를 프롬프트에 명시, 자동 호출 없이 원할 때만).

### v20에서 바뀐 점 (AI 원맨쇼·3인칭 서술 방지, busy 중 클릭 씹힘 해결, 사전 진단 선다형 혼합)
- **AI의 원맨쇼·3인칭 서술 방지(원리10)** — "혼자서 해야 할 생각을 굳이 말로 드러낸다", "학습자가 하지 않은 말을 하고 혼자 응답한다"는 지적. 시스템 프롬프트에는 이미 금지 규칙이 있었는데도 새어 나왔다 — 학습자를 3인칭 "학습자가/는"으로 서술하거나(속으로만 판단할 것을 말로 냄), "…라고 답했다고 치고"·"학생:/AI:" 라벨로 두 역할을 혼자 다 쓰는 패턴을 새로 감지하는 필터를 `hasMetaLeak`/`stripMetaLeak`에 추가했다. 기존과 같은 방식(감지 시 1회 재시도 → 그래도 남으면 그 줄만 제거)으로 처리한다.
- **busy(AI가 응답 중)일 때 클릭이 조용히 사라지는 문제 해결(원리10)** — "체크리스트 검토나 기타등등, 학습자가 응답해줘도 AI가 체크를 못하는 일이 생긴다"는 반복 지적의 실제 원인을 찾았다: AI가 이전 응답을 만드는 동안(`busy`)에도 "🔍 다 했어요"·체크리스트·전송 버튼 등은 그대로 눌려서, 각 함수 맨 위 `if(busy) return;` 가드에 아무 안내 없이 씹혔다. 학습자 입장에서는 분명히 답했는데 AI가 못 본 것처럼 보인다. 이제 `busy`인 동안 대화창 전체를 시각적으로도 잠가(옅게, 클릭 안 됨) 응답을 기다려야 한다는 게 눈에 보이게 한다.
- **사전 진단(가 단계)에 선다형 혼합(원리6)** — "너무 텍스트 쓰기만 주지 말고 선다형도 섞어달라"는 요청. 기억해내기·예시 들기 문항은 4지선다로, 자기 말로 설명하기·적용하기 문항은 그대로 서술형으로 남긴다(전부 선다형으로 바꾸면 "자기 말로 설명"이 성립하지 않아서다). 채점은 고른 선택지의 문구를 그대로 답으로 써서 기존 채점 로직을 그대로 재사용한다.

### v21에서 바뀐 점 (설계원리 세부 지침 대비 점검 및 반영)
사용자가 전달한 "설계원리 별 세부 지침" 문서를 코드와 한 줄씩 대조해 찾은 미반영·불완전 구현 6가지를 반영했다.
- **원리3 [설계 전체 지침] 2 — 개인정보 팝업 누락**: 전화번호·이메일·주민번호 패턴은 `anonymize()`가 조용히 가려서 저장만 하고, 지침이 요구하는 "개인정보·민감정보는 채팅 창에 쓰지 말아달라"는 팝업은 한 번도 띄우지 않고 있었다. 실제로 패턴이 걸렸을 때만 안내 팝업을 띄운다(매 입력마다 뜨면 방해가 되니).
- **원리1 [대화 중 지침] 2·3 — 도움 하향을 시스템이 임의로 실행**: "이해도가 좋으면 AI가 하향을 제안하고, 줄일지는 학습자가 선택한다"고 되어 있는데, 실제로는 좋아요·이해도 체크포인트가 2번 연속 좋으면 시스템이 그 자리에서 바로 줄여버렸다(제안·선택 단계가 없었다). `fade()`를 "제안 카드 + [줄여볼래요]/[그대로 둘래요] 선택"으로 바꾸고(`proposeFade()`), 실제 반영은 학습자가 고른 뒤에만 일어나게 했다.
- **원리12 [대화 이후 성찰 지침] 2 — 프롬프트 리커트 평가 부재**: "학습자가 고른 프롬프트를 구체성·논리성·명시성 리커트척도(1~5)로 스스로 체크"하는 기능이 없었다(질문 목록을 읽기만 했다). 되짚기 나 단계에서 질문 하나를 직접 고르면(누를 수 있게 바꿈) 세 축을 1~5로 스스로 매기는 패널이 뜬다.
- **원리3 [메인 대시보드 설계 지침] 1·2·3·4 — 대시보드 그래프 다수 미구현**: (1) 인지전략 효과성 지표가 없어 빈도만 보였다 → 그 방법을 쓴 세션의 사후(혼자 풀어보기) 점수 평균을 함께 표시. (2) 인지적 잔여도의 "과목별 꺾은선"이 없었다 → 과목마다 다른 색 선 추가 + "과목별 향상 평균" 막대그래프 신설. (3) 프롬프트 지표(구체성·논리성·명시성) 그래프가 통째로 없었다 → 위 리커트 데이터를 평균 막대 + 회차별 꺾은선으로 신설. (4) 메타인지 지식 지표 꺾은선이 없었다 → 나 단계 점수를 회차별 꺾은선으로 신설.
- **원리13 [대화 이후 성찰 지침] 3 — 잔여물 확인 후 성찰일지 누락**: "어려웠던 점이나 새롭게 알게 된 점을 성찰일지로 남기도록" 했는데, 결과 판단(나아졌어요/할 말 있어요)만 있었지 이 자유 서술 칸이 따로 없었다. 혼자 풀어보기 결과 화면 마지막에 성찰일지 칸을 추가했다(지난 공부 기록 상세보기에서도 다시 볼 수 있다).

**검토했지만 이번엔 반영을 보류한 것(다음 라운드 논의 필요)**: 원리5 지침2가 요구하는 "가변 블록=슬라이더(연속 AI 의존도)/역할고정협업 블록=토글" 구분 — 지금은 모든 이동 가능 블록이 AI/나 둘 중 하나를 고르는 클릭 방식이다. 문항 값이 이진(AI가 하나, 내가 하나)인 과업에 연속 슬라이더가 실제로 무엇을 뜻하는지 모호해, 무리하게 UI만 바꾸면 예전에 고쳤던 "블록이 너무 많고 헷갈린다"는 문제가 재발할 위험이 있어 보류했다. 원리5 지침3(최근 설정 내역 참고 제공)·원리10 지침3(AI 응답의 출처·산출 과정 제공)도 아직 미반영이다.

- **플로우차트 아티팩트 가시성 개선** — 카드 사이에 굵은 화살표를 넣어 실제 흐름도처럼 보이게 하고, 단계 번호 배지·스테이지별 색 배경·8단계 빠른 이동 바를 추가했다. 나선형 순환 다이어그램의 글자 대비·선 굵기도 키웠다.

### v23에서 바뀐 점 (과업 분담 정리, 원리5·10 남은 지침 반영)
- **과업 분담을 진짜 회색지대 4개로 정리(원리5)** — "과업 분배가 여전히 어색하다, 필요없는 건 버려라"는 지적. concept·checkwork(늘 AI가 함)와 strategy_choice·connect_make·self_judge·reflect_write(늘 내가 함) 6개는 애초에 옮길 수 없는 고정값이라, 골라볼 수 있는 것처럼 화면에 늘어놔 봐야 결정할 게 없는 항목만 쌓여 있었다(🔒 잠금 표시 2줄). 이 6개를 화면에서 뺐다 — 실제 동작(AI가 설명·채점하고, 학습자가 전략을 고르고 판단·성찰을 직접 쓰는 것)은 코드 다른 곳에서 그대로 유지되고, 여기서는 "예시 들어주기·다음에 뭘 할지 정하기·의심 가는 부분 찾기·배운 내용 정리하기" 4개, 진짜 고를 수 있는 것만 남긴다.
- **최근 설정 참고를 안내 문구로 노출(원리5 지침3)** — 시작할 때 AI 힌트 크기가 지난 선택으로 미리 맞춰지는 동작 자체는 있었지만 왜 그렇게 맞춰졌는지 학습자에게 보여준 적이 없었다. "지난 공부를 마치며 다음엔 ~로 하겠다고 골라서 미리 맞춰뒀어요" / "지금까지 ~를 제일 자주 골랐어요" 안내 문구를 추가했다.
- **AI 응답에 "왜 이렇게 말했어?" 설명 버튼(원리10 지침3)** — 지원강도·과업분담 같은 내부 설정값은 언급하지 않고, 오직 학습자가 대화에서 실제로 한 말에 근거해서만 그 응답이 왜 나왔는지 쉬운 말로 설명해준다.

### v24에서 바뀐 점 (힌트 크기 제거, 과업분담 PDF 반영, 인지전략=탐구 1단계, 프롬프트 복수선택, 잔여물 쌍둥이과제)
사용자가 준 세부지침 7가지를 반영했다.
1. **AI 힌트 크기 선택 제거** — 세션 시작 화면의 "① AI 힌트 크기(많이/보통/조금)"와 잔여물 확인 결과 화면의 "다음 공부 AI 도움" 선택을 없앴다. 어려울 때 AI가 도와주는 것(비계)은 이제 아래 "가"(늘 AI가 하는 일)에 포함돼 항상 일어나고, 이해도가 좋아지면 대화 중 제안→선택으로 계속 자동 조절된다(원리1, v21의 proposeFade 그대로 유지). 두 설정이 겹쳐 있어 어색하다는 지적이 반복돼 하나로 합쳤다.
2. **과업 분담 블록을 PDF 원문대로 재작성** — 추측해서 붙였던 라벨(concept·checkwork·strategy_choice 등)을 걷어내고, [원리5 · 대화 전 설정 지침 1]의 가(고정·AI: 근거 자료 찾아주기·비계 설정하기·채점 및 피드백하기)·나(고정·학습자: 공부법 돌아보기·내 생각 판단하기)·다(유동적 5개: 문제 정의·결과물 설명·핵심 요약·초안 작성·복잡한 문제 구조화)를 그대로 옮겼다. 가·나는 나열식 블록이 아니라 초등학생도 읽을 짧은 설명 두 줄로, 다 5개만 AI/나 블록으로 옮길 수 있게 뒀다.
3. **인지전략 선택을 대화 탐구의 1단계로 재배치** — PDF에서 원리8(인지 전략 계획 수립)은 "학습 맥락 구성(준비)"이 아니라 "대화 과정(탐구)" 계열에 속한다. 나(스스로 점검) 단계가 끝나면 곧바로 phase를 'explore'로 넘기고, 방법을 고르고 이유를 말하는 것까지를 탐구의 시작으로 다시 배치했다(session.cycleStarted로 실제 순환 시작 시점만 별도로 구분).
4. **대화 탐구가 "그냥 대화"로 변질되지 않았는지 확인** — apply 단계 지시문은 이미 "이번엔 ~를 해보자"처럼 실제 과업을 단정적으로 내고, 사전 진단과 똑같은 형태로 재탕하지 않고 새 상황에 적용(전이)하게 못박아 뒀다. 소크라테스식 발문(ask)은 과업 수행 앞의 짧은 도입일 뿐, 핵심은 여전히 apply의 실제 과업 수행이다.
5. **표·마인드맵을 AI가 못 읽는 문제** — describeStruct()가 학습자가 실제로 채운 표 칸·마인드맵 낱말·비교 내용을 그대로 읽어 reviewStruct()의 AI 피드백 지시문에 넣는 구조가 유지돼 있음을 재확인했다(v15~v19에서 고친 것이 계속 살아있다).
6. **프롬프트 성찰을 복수 선택으로** — 질문 하나만 고르던 것을 원하는 만큼 여러 개 고를 수 있게 하고, 고른 질문마다 각각 구체성·논리성·명시성 리커트 카드를 띄운다(session.reflect.promptRating → promptRatings 배열). 대시보드 막대는 모든 개별 채점의 평균, 꺾은선은 세션별 평균 1점으로 다시 집계.
7. **잔여물 확인을 "쌍둥이 과제"로** — 사후 진단에서 방법을 다시 고르게 하던 화면을 없애고, 대화 중 실제로 썼던 전략(session.strategies)을 문항 4개에 순서대로 짝지운다. 출제 프롬프트에도 "이 문항은 그 방법으로 풀기 좋은 쌍둥이 문제"라고 명시.

### v25에서 바뀐 점 (카드 예고 유출 방지, 팁 인용 유출 방지, 비판적사고 과목별 프레이밍, 전략별 추천 조건, 예시 데이터)
스크린샷으로 확인된 실제 대화 이상 증상 5가지를 반영했다.
1. **"(전략 카드 뜰 거야)" 같은 화면 예고 유출** — 나 단계(스스로 점검) 중 AI가 "(인지전략 카드 뜰 거야)", "(메타인지 카드 뜰 거야)"처럼 아직 뜨지도 않을 화면 요소를 미리 말로 예고해 학습자가 "카드 안 뜨는데요?"라고 혼란스러워했다. hasMetaLeak/stripMetaLeak에 "카드"를 포함한 괄호 패턴을 추가하고, 직접 화법 규칙에도 명시적으로 금지했다.
2. **tips 예시를 인용부호로 그대로 보여줬다가 베껴 말하는 문제** — apply 단계 지시문에 `"${strat.tips[...]}"`처럼 인용부호로 예시를 보여줬더니, AI가 그 예시를 "💡 ~예시. (tip 그대로)"처럼 거의 베껴 말해버려 "이상한 소리·부실한 피드백"으로 느껴졌다. 인용부호를 빼고 "내부 참고용, 그대로 옮기지 말 것"을 명시.
3. **비판적 사고 전략이 모든 과목에 "반례 찾기"로 기계적으로 대응돼 어색해지는 문제** — "영국 명예혁명이 인권확장에 미치는 영향"처럼 반례가 어색한 과목(국어·사회·도덕)은 "다른 해석·관점·반박 근거"로, 반례가 자연스러운 과목(수학·과학 등)은 그대로 반례로 비교 과업의 제목을 짓게 분기했다(STRUCT_SCHEMAS.compare.ask, apply 지시문 둘 다).
4. **전략별 추천 조건 명시** — 5개 인지전략 각각에 "이럴 때 특히 도움돼요"(recommendWhen)를 추가해 전략 카드마다 보여주고, 지금 내 점수와 가장 잘 맞는 전략에는 "⭐ 지금 나한테 잘 맞을 수 있어요" 배지를 붙였다.
5. **"내 정보" 요약이 와닿지 않는 문제** — 말로만 뭉뚱그린 표("조금씩 알아가고 있어요") 대신, 실제 0~100 점수를 다른 곳과 같은 시각 언어(막대)로 보여주고, 맨 위에 지금 상태를 있는 그대로 풀어 쓴 문장을 하나 추가했다.
6. **고1 국·영·수·사·과 예시 데이터 채우기** — 대시보드 위젯이 데이터가 쌓이면 어떻게 보이는지 미리 보기 쉽도록, 예시 세션 5개를 한 번에 채우는 버튼을 추가했다(isSample 표시로 실제 기록과 구분, 지우기 버튼도 함께 제공).

### v26에서 바뀐 점 (웹앱·플로우차트·설계지침 PDF 정합성 최종 점검)
"웹페이지 UI/UX, 플로우차트, 설계지침 간 정합성을 점검하고 안 맞으면 PDF를 기준으로 고쳐라"는 요청에 따라 13원리 지침을 한 줄씩 다시 대조해 찾은 것들이다.
- **원리5-지침2 미반영을 마저 반영** — "가변 블록은 슬라이더(AI 의존도 연속 조절), 역할고정협업 블록은 토글(AI 호출 여부만 선택)"이 v21부터 보류 상태였다. 다(유동적) 5개를 클릭식 이동에서 0~100 슬라이더로, 가(고정·AI) 3개를 "AI가 바로 나설지" 토글로 바꿔 PDF 문구 그대로 구현했다(나는 AI가 애초에 할 수 없는 일이라 토글 대상이 아니다). 토글을 끄면 그 항목만 AI가 먼저 나서지 않고 학습자가 시도할 때까지 기다린다(역할 자체는 그대로 AI 몫).
- **원리5-지침3(최근 설정 참고)의 대상을 재조정** — 힌트 크기 선택이 없어진 지금은 이 지침이 적용될 유일한 설정이 과업 분담이라, 지난 세션의 슬라이더·토글 값을 시작값으로 이어받고 안내 문구를 붙였다.
- **실제 버그 발견·수정: 과업 분담 값이 숫자로 바뀌면서 세션 상세보기가 옛 문자열('ai'/'me')과 비교하고 있었다** — `openSessDetail()`의 tbAi/tbMe 계산이 새 슬라이더 값(숫자)을 인식하지 못해 "그때 할 일 분담"이 항상 비어 보이는 회귀 버그였다. 50 기준 임계값 비교로 맞췄다.
- **원리10-지침3("대화 전반의 지침")과 범위 불일치 수정** — "왜 이렇게 말했어?" 버튼이 탐구(explore) 단계 말풍선에만 떴는데, 같은 지침을 따르는 "판단하기" 버튼은 모든 단계에 뜬다. PDF가 "대화 과정 전반"이라고 명시하므로 범위를 맞춰 전체 단계로 넓혔다.

### v27에서 바뀐 점 (설계원리–시스템 정합성 개선)

**A. 대화 중 원리가 실제로 작동하지 않던 구조 버그**
1. **시스템 프롬프트 절단 수정** — `[system, ...이력].slice(-16)` 때문에 16턴이 넘으면 시스템 프롬프트(성취기준·전략·과업 분담·[이번 지시])가 잘려 나갔다(보통 첫 "방법대로 과제" 턴부터). `buildMessages()`로 시스템 메시지를 항상 유지하고 이력만 18개로 자른다.
2. **산출물·체크포인트를 이력에 포함** — 표·마인드맵은 `(표/마인드맵 결과)` 자리표시로만 전달되던 것을, 학습자가 채운 내용을 구조 그대로(열 이름=값, 중심 낱말—[관계]→낱말) 이력에 넣는다. 이해도 체크포인트·다시 떠올리기·아는 것 확인 답도 AI가 본다.

**B. 원리 2와 원리 5·6·9의 충돌 해소**
3. 시스템 규칙 "정답 여부를 AI가 판정하지 말라" → "근거를 들어 진단하되 판결하지 말고, 수용·자기 이해 판단은 학습자에게"로 재정의.
4. **과업 명세(task spec)** — apply 단계에서 {과업, 핵심 내용, 결과물 형태, 성공 기준, 예상 착오}를 먼저 생성·저장하고, 성공 기준을 과업 아래 카드로 보여준다(원리9 자기점검 준거).
5. **AI 피드백(원리9-1·9-3)** — check 단계에서 시도를 성공 기준에 비추어 진단(`evaluateAttempt`, temperature 0)하고, 해낸 점·더 볼 점·착오 유형(추정)을 근거 카드로 보여준 뒤 동의 여부·전략 효과를 학습자에게 묻는다. 표·마인드맵 "다 했어요"도 같은 진단을 쓴다.
6. 과업 대기 중 학습자가 질문·도움 요청을 하면 순환을 넘기지 않고 힌트만 준다. 전략 완료는 "2바퀴"가 아니라 진단 결과(일부 이상 충족) 또는 3바퀴 기준.

**C. 원리 8 인지전략–과업 정합성**
7. 세션 시작 시 내용 성격(사실·개념·절차·인과·해석) 분류 → 전략 카드에 "📘 오늘 내용에 잘 맞아요"(내용 적합도)와 "⭐ 지금 나한테 도움될 수 있어요"(학습자 점수)를 따로 표시. 적합도 표(`STRAT_FIT`)는 연구진이 조정 가능.
8. 모든 전략에 "새 상황 적용(전이)"을 강제하던 지시와 무작위 팁을 제거하고, 전략별 과업 원칙(`STRAT_TASK_GUIDE`)으로 교체. 조직화는 인과·절차 내용이면 순서 사슬을 추가 제공. 활동판 재료는 성취기준 전문이 아니라 지금 과업에 맞춘다.

**D. 측정(원리 1·3·6·7·13)**
9. 사전 확인: 출제 시 정답 키·루브릭 동시 생성, 선다형은 코드 채점, 서술형은 3수준(0/50/100) 루브릭 + temperature 0. 활성도·이해도·적용력 하위 점수(지침 6-2).
10. 메타인지: 질문별 답을 분리 채점, 기준점 있는 루브릭, 평소 공부법 포함. 자기 이해 정확도는 LLM 판정 대신 **보정도**(사전 자신감 vs 실제 점수)로 계산해 표시.
11. 사후(혼자 풀어보기): 사전과 같은 유형·난이도의 **평행 문항**으로 바꿔 전후 비교를 유효하게 함. 영역별 전후 변화 행 추가. 자신감 오차는 점수 기반 Brier.
12. 비계 감소 제안: '좋아요' 연속(수용≠이해) 대신 과업 진단 2회 연속 "대부분 충족" 또는 체크포인트 고점 연속(최근 진단이 미충족이면 보류).
13. 대시보드 전략별 효과: 사후 없을 때 사전 점수로 대체하던 것을 없애고 사전→사후 변화만, 복수 전략은 가중 분배, 횟수 표시.

**E. 그 밖의 지침 보완**
14. (원리3) 대화 시작 시 개인정보 주의 안내, 이름 자기소개·학교명·주소·긴 숫자까지 가림, AI 출력에도 동일 필터.
15. (원리4) 매칭된 성취기준의 해설을 보여주고 "내 목표와 맞는지 확인" 체크 후 시작.

### v28 — 새로 배포할 때 저장소 선택 (Google 시트 없이도 가능)
`api/_store.js`는 Google 시트 변수 3개가 있으면 시트를, 없으면 **Upstash Redis**를 저장소로 쓴다.
새 Vercel 프로젝트에서는 대시보드 **Storage → Create Database → Upstash for Redis(Free) → Connect** 만 누르면
`KV_REST_API_URL`·`KV_REST_API_TOKEN`이 자동 등록된다. 그 밖에 필요한 환경변수는 `UPSTAGE_API_KEY`, `AUTH_SECRET` 두 개뿐.
손글씨 인식(Cloud Vision)은 Google 설정이 있을 때만 동작한다.

### v31 — 교사용 관리, 끝내지 않은 공부 보존
- **교사용 관리 화면** `/teacher.html` (Vercel 환경변수 `TEACHER_KEY` 필요): 학생 목록, 세션 요약 CSV·전체 원자료 JSON 내려받기, 학생 그림 비밀번호 초기화. API는 `POST /api/teacher` (Redis 저장소에서 동작).
- **끝내지 않은 공부도 기록에 남김**: 임시 저장본을 [그만하기]하거나 새 공부를 시작하면 "미완료"로 기록에 옮긴다(통계에서는 제외, 목록에는 ⏸ 표시). CSV에는 completed / incomplete / in_progress 로 구분.
- 예시 데이터 채우기 버튼은 주소에 `?demo`를 붙였을 때만 보인다.
- 내 공부방 "주고받은 말" → "내가 보낸 말"로 이름과 셈 기준을 통일.
